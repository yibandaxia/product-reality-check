# Example — Freelance Payment Reminder

## Starting idea

> I want to build a tool that reminds freelancers when clients are late paying invoices.

## Why this idea looks stronger than it first appears

The key is not that late payment is annoying. The key is whether freelancers already exhibit costly behavior around it.

## Discovery path

### 1. Look for existing effort

Ask:

> What do freelancers do today when invoices are overdue?

Possible answers:

- maintain spreadsheets
- schedule calendar reminders
- send manual follow-up emails
- use accounting software
- avoid chasing because it feels uncomfortable

This creates observable behavior to study.

### 2. Identify the real pain

The problem may be less about remembering due dates and more about:

- awkward client communication
- inconsistent follow-up
- cash-flow uncertainty
- lack of escalation rules

A reminder alone may therefore be too weak.

### 3. Test willingness to pay

Instead of asking:

> Would you pay $10 per month?

Ask:

> What tools do you already pay for to manage invoices, contracts, bookkeeping, or client communication?

This reveals the existing spending context.

### 4. Explore product forms

Possible directions:

- lightweight reminder utility
- automated follow-up email assistant
- invoice aging dashboard
- plugin for existing accounting tools
- service for high-value freelancers or small agencies

### 5. Minimum validation

Offer a manual service to 10–15 freelancers:

- they forward invoice details
- overdue invoices trigger pre-written follow-up sequences
- track whether clients pay faster
- measure whether freelancers continue using the service

## Example diagnosis

**Demand status:** Real problem, business-model strength still unknown.

**Critical assumption:** Users value automated follow-up enough to pay separately from existing accounting software.

**Cheapest next test:** Manual overdue-invoice follow-up service integrated into the user's existing workflow.
